- **Object storage.** Accounts can keep S3-compatible buckets on the server, served by Silo, the community-maintained fork of MinIO, installed from checked packages under Server → Object storage (`v-add-sys-silo`) and published on a hostname of its own with Let's Encrypt (`v-change-sys-silo-endpoint`). Packages say whether an account may use it, how many buckets it may have, how much their quotas may add up to and whether user backups include the objects (`OBJECT_STORAGE`, `OBJECT_STORAGE_BUCKETS`, `OBJECT_STORAGE_QUOTA`, `OBJECT_STORAGE_BACKUP`); resellers stay within their own package. The Object storage page lists the buckets with quota, usage and versioning, adds S3 keys for every bucket of the account or one bucket, read and write or read only, with an optional expiry, and shows a new key's secret once; it can also be saved in the secret store. Buckets are suspended, restored and deleted with their account, and user backups keep their settings. REST API v2 answers `/users/{user}/buckets`, `/users/{user}/s3-keys`, `/buckets` and `/system/object-storage`, with the permission set `v2-storage`.
- **S3 backup host.** Incremental backups can go to an S3-compatible bucket (AWS, Cloudflare R2, Wasabi, the object storage of another ArcPanel server): "S3-compatible bucket" under Server → Settings → Backups, or `v-add-backup-host-s3`. The connection is kept as an rclone remote of root; the form shows the endpoint, region and access key ID, never the secret.
