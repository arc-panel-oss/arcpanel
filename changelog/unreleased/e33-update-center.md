- **Update Center.** Server → Updates shows the installed version, the releases of the signed release manifest of `apt.arcpanel.org` with the reason each one is or is not installed on its own, the update policy, the installed packages and the history of updates. An administrator updates to a chosen release after a pre-flight check (free disk, package manager, running tasks and backups); a minor or major release, or a patch release flagged for attention, lists what changes and waits for each item to be confirmed. After every update a health check tests the services, the panel, the web server configuration, the firewall and the packages, and compares up to five sites with their answers before the update; a site that answers differently is reported as a warning only, since a customer controls it.
- **Update policy.** `off` checks nothing; `notify` checks every hour and announces new versions with a panel notification and an e-mail, once per version; `patch` also installs the patch releases of the installed line that need no attention. Installs happen in a maintenance window of week days and hours of the server (`UPDATE_WINDOW_DAYS`, `UPDATE_WINDOW_HOURS`, for example `03-05`, which may wrap past midnight) and only once a release is `UPDATE_DELAY_DAYS` old, 2 by default; a security release skips the delay. A release withdrawn in the manifest is never installed on its own. Set the policy on the Updates page, with `v-change-sys-update-policy` or in `PATCH /api/v2/system/updates/policy`; to stop automatic installs, choose `notify`, or `off` to stop the checks too.
- **Rollback.** When the health check fails after a patch release without upgrade steps, the server installs the previous version of its line again and restores the configuration saved before the update, then alerts the administrator; the Updates page, `v-rollback-sys-arcpanel` and `POST /api/v2/system/updates/history/{id}/rollback` do the same by hand for the newest update. A release with upgrade steps, a minor or major release or one whose previous version is no longer in the repository is not rolled back: a failure pauses automatic updates until an administrator resumes them.
- REST API v2: `listPanelReleases` (its `refresh` only for a key that may run updates), `checkPanelRelease`, `getUpdatePolicy`, `setUpdatePolicy`, `listUpdateHistory`, `rollbackPanelUpdate` and `resumeAutoUpdates`; `runUpdates` takes a release `version` (with `confirm_attention` for releases that need attention).
