- Long operations run as jobs (E15): system tasks (`sys.*`), the Docker engine install (`docker.engine`), Docker app tasks (`docker.install`, `docker.update`, `docker.rollback`, `docker.snapshot`), Node.js tasks (`node.install`, `node.npm`, `node.build`), app process tasks (`app-process.*`), Quick Install (`quick-install`), background malware scans (`malware.scan`), backups and restores (`backup.*`, `restore.*`), Let's Encrypt certificates (`letsencrypt.domain`), Git deploys (`deploy.run`, `deploy.rollback`), the runs of backup jobs (`backup.job`) and uploads from URL (`fs.fetch`). Every `v-start-*` and `v-schedule-*` command keeps its arguments and prints the job ID; the job, its log and its result are read with `v-list-job`.
- The old task records (`data/sys-task/`, `data/docker/engine-task.state`, the `task.state` of Docker apps, `node-task.conf`, `app-process-task.conf`, `quick-install-task.conf`, `malware/task.conf`, `data/users/USER/tasks/`) are no longer written. `v-list-sys-task`, `v-list-sys-docker-task`, `v-list-docker-app-task`, `v-list-user-node-task`, `v-list-app-process-task`, `v-list-user-quick-install-task`, `v-list-user-malware-task` and `v-list-user-tasks` read the newest job in their old format; they are deprecated and go in 3.1.
- The runner commands take the job's arguments instead of a task ID and refuse to run outside their job: `v-run-sys-task KIND [ARG...]`, `v-run-sys-docker-task [DATA_ROOT]`, `v-run-docker-app-task USER NAME ACTION [VERSION]`, `v-run-user-node-task USER ACTION [ARGS...]`, `v-run-app-process-task USER DOMAIN NAME TASK [COMMAND]`, `v-run-user-quick-install USER DOMAIN APP` and `v-run-web-domain-deploy USER DOMAIN ACTION [VALUE]`.
- The backup and Let's Encrypt queue pipes (`data/queue/backup.pipe`, `data/queue/letsencrypt.pipe`) and `v-run-queue-task` are gone: the job queue runs one backup or restore and one certificate at a time (`JOB_BACKUP_PARALLEL`, `JOB_LETSENCRYPT_PARALLEL`) and retries a failed one up to `QUEUE_MAX_ATTEMPTS` times. `v-update-sys-queue backup` and `letsencrypt` run the job queue until the upgrade replaces their cron lines. A backup and a restore of the same user no longer wait together: the second is refused while the first is queued or running. The output of queued backups and restores is in the job log instead of `log/backup.log` and `log/restore.log`.
- A newer Git deploy request replaces the queued one as `cancelled` with the error "replaced by ID"; turning deploy off cancels its jobs. The backup runs of a backup job record their job (`JOB` of `data/backup/runs/`), uploads from URL record theirs (`JOB` of the fetch record), and the per-user backup runs and the update runs keep the job ID in `TASK`.
- The options of a Quick Install are kept root-only with the job for a day after a failure, so that the install can be retried; they are removed when it succeeds.
