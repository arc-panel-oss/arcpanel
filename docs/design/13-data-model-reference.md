# 13 — Data Model Reference

**Epics:** all · **Status:** Draft v1

The one place that lists every file, key, directory and command the ArcPanel designs add on top of HestiaCP 1.10.5. Per-epic documents explain _why_; this one answers "where does X live and who writes it". Keep it in sync when a design changes.

Conventions: `$HESTIA` = `/usr/local/hestia`; `~` = `/home/<user>`; `data/…` = `$HESTIA/data/…`. Ownership `root:user 0640` means the file is readable by root and the owning hosting user only. **All hosting state stays in Hestia's flat files**; the panel reads it through `v-list-*` JSON. The only database is the post-2.0 SQLite file in §6.

---

## 1. Design rules for new data

1. **Hestia object format** for anything a `v-list-*` command exposes: one object per line, `KEY='value'` pairs separated by spaces, keys upper-case, plus `SUSPENDED`, `TIME`, `DATE` where the object has a lifecycle. This keeps `func/main.sh` helpers (`is_object_valid`, `parse_object_kv_list`, `get_object_value`) usable.
2. **Authoritative record inside the user's tree** when the object must survive `v-backup-user` / `v-restore-user` without touching upstream backups (Node apps, Docker apps, template variables); a derived **index** under `data/users/<user>/` for cheap listing, rebuilt by `v-rebuild-*`.
3. **Root-only** for registries and secrets (`data/ports`, `data/secrets`, `data/audit`); **root:user 0640** for per-user records a user may read via SFTP; **hestiaweb-owned** only for the panel's own operational files under `web-app/storage` and `data/arcpanel`.
4. **Additive keys** in `user.conf`, `.pkg` and `hestia.conf`: upstream `source_conf` ignores unknown keys; new keys default to the pre-ArcPanel behaviour when absent.
5. **Schemas** for JSON/YAML files live in `docs/design/schemas/` and are validated in CI (`v-check-web-template-meta`, `v-check-docker-catalog`, `v-check-sys-packages`).

## 8. Identifiers and naming

| Thing                                      | Pattern                                                                                                        | Example                                           |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Port registry `APP`                        | `<kind>:<id>` — `node:<domain>`, `docker:<slug>`, `manual`, empty for an unassigned block                      | `docker:uptime-kuma`                              |
| Firewall rule comment for registry ports   | `arcpanel:<user>:<port>`                                                                                       | `arcpanel:alice:30002`                            |
| Docker Compose project                     | `ap-<user>-<slug>`                                                                                             | `ap-alice-uptime-kuma`                            |
| pm2 user unit                              | `pm2-<user>.service` in `~/.config/systemd/user/`                                                              | `pm2-alice.service`                               |
| Template variables                         | `%<name>%` with `name` `^[a-z][a-z0-9_]*$`, declared in the sidecar                                            | `%node_port%`, `%docker_port%`                    |
| Capabilities / audit actions / route names | `<module>.<object>.<action>`                                                                                   | `web.domains.create`, `users.update`              |
| Laravel routes                             | `/app/<module>/…` until E8, then `/<module>/…`; JSON for islands under `/app/<module>/api/…`                   | `/app/files/api/list`                             |
| Blade components                           | `<x-ap-*>`                                                                                                     | `<x-ap-table>`                                    |
| Vue islands                                | `data-island="<name>"`                                                                                         | `data-island="file-manager"`                      |
| WebSocket control frame                    | first message JSON `{"type":"tail","target":"<kind>:<id>"}`; non-JSON first message = shell (legacy behaviour) | `{"type":"tail","target":"node:api.example.com"}` |
| Secrets paths                              | `data/secrets/<user\|system>/<kind>/<name>`                                                                    | `data/secrets/alice/dns/cloudflare-main`          |
| Job ids / audit ids                        | ULID                                                                                                           | `01J9…`                                           |
