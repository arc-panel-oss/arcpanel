# 08 — App Store (Docker apps and system packages)

**Epics:** E4 (Docker apps), E5 (apt/snap system apps) · **Status:** Draft v1 · **Depends on:** E1, E6 batch 1 (`docker-proxy*`, [09](./09-web-templates-metadata.md)), E12 ([04](./04-port-registry.md)), E11 for owner scoping · **Unblocks:** E33 (Docker updates in the Update Center), E6 batch 2–3 runtimes

---

## 1. Goal

A non-expert user picks an app from a curated catalog, binds it to one of their domains and gets it running with HTTPS; they can see its status and logs, change its settings, update it and remove it cleanly — without SSH. Admins install the runtimes and services that templates and apps need (Python, Go, Redis, FFmpeg, …) from the same store.

Non-goals: arbitrary `docker run`, user access to the Docker socket, Kubernetes, multi-host, image building from user Dockerfiles (post-2.0 candidate).

---

## 2. Current state (verified in code)

- No Docker support anywhere in `bin/`, `func/` or the installer. `nodejs` is installed system-wide only for the web terminal.
- Per-user resource limits exist as systemd slices (`v-update-user-cgroup`: `CPUQuota`, `MemoryHigh`, `MemorySwapMax` on `user-<uid>.slice`).
- `v-backup-user` has **no hook points**: it archives `~/web`, DNS, mail, databases, cron and then every other directory in the user's home (`ls -a | egrep -v "^conf$|^web$|^dns$|^tmp$|^mail$"`) as `user_dir/<dir>.tar.{gz,zst}`, honouring `USER=` exclusions from `backup-excludes.conf`. `v-restore-user … UDIR` restores those directories. Only `user.conf`, `ssl/`, `stats.log`, `history.log` and `backup-excludes.conf` are copied from `$USER_DATA`.
- Long operations are queued through `data/queue/*.pipe` and run by `v-update-sys-queue <pipe>` from the `hestiaweb` crontab (`*/2` for restart, `*/5` for backup).
- Quick Install Apps (`web/src/app/WebApp/Installers/*`) are PHP installers into `public_html`; they are unrelated to Docker and are migrated in E7 ([10](./10-page-migration-and-retirement.md)).

## 3. Docker engine mode (ADR-0003)

**Recommendation for 2.0: one root Docker Engine, per-user Compose projects operated only by `v-*` commands.** Rootless Docker per user is rejected for 2.0.

| Aspect          | Root engine + root-run Compose (chosen)                                                                                                        | Rootless Docker per user (rejected for 2.0)                                                                     |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Setup           | `apt install docker-ce docker-compose-plugin` once (`v-add-sys-docker`)                                                                        | per-user `dockerd-rootless-setuptool.sh`, `systemd --user`, linger, subuid/subgid ranges for every hosting user |
| Networking      | native bridge, `127.0.0.1:<port>` publish, full speed                                                                                          | slirp4netns/pasta user-mode networking: slower, no `--net=host`, port publish quirks                            |
| Volumes         | bind mounts under `/home/<user>/apps/<app>/data`, chowned to the user; images that run as a fixed uid get `user: "<uid>:<gid>"` when supported | file ownership mapped through subuids; backups see shifted uids; restore across servers needs identical maps    |
| Isolation       | kernel namespaces + the panel never exposing the socket; a container escape is root (same as upstream services like Exim running as root)      | container escape is the user — genuinely better                                                                 |
| Resource limits | `cpus`/`mem_limit` per service from the package; the containers are not in the user's slice                                                    | containers inherit the user slice automatically                                                                 |
| Ops             | one daemon, one log, one upgrade path, well understood                                                                                         | N daemons, N upgrade paths, debugging per user                                                                  |

Why the trade-off is acceptable: users never run `docker` themselves (no socket, no group membership); every Compose file is **generated by the panel from a curated manifest** (users set variables, not YAML); images come from a pinned catalog; `privileged`, `cap_add`, host mounts outside the app dir, `network_mode: host` and the Docker socket are forbidden by the manifest schema and checked at render time. The remaining risk is a kernel/container escape in a curated image — accepted for 2.0 and recorded in the ADR. Rootless (or Podman) stays a post-2.0 option: the manifest/compose contract is engine-neutral, and `func/docker.sh` is the only place that would change.

## 4. Concepts

| Term               | Definition                                                                                                                               |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **Catalog**        | the set of app manifests shipped in `install/common/apps/docker/` and refreshable from a Git URL                                         |
| **Manifest**       | `manifest.yaml` + `compose.yaml.tpl` for one app and version line                                                                        |
| **App (instance)** | one installed manifest for one user, bound to one domain: Compose project `ap-<user>-<app>` in `/home/<user>/apps/<app>/`                |
| **Variables**      | typed inputs declared by the manifest, rendered into `.env` of the project (secrets generated when blank)                                |
| **Web port**       | the single container port exposed to NGINX on `127.0.0.1:<registry port>` through the `docker-proxy*` template                           |
| **Extra ports**    | optional additional ports (e.g. MinIO S3 API, Gitea SSH) — each also from the registry; public only through the registry's `PUBLIC` flag |

## 5. Docker apps (E4)

### 5.1 Data

| Location                                                                                       | Content                                                                                                                                                                                                 | Owner          |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| `install/common/apps/docker/<slug>/manifest.yaml`, `compose.yaml.tpl`, `icon.svg`, `README.md` | catalog source, copied to `/usr/local/hestia/data/apps/catalog/docker/` at install/upgrade and by `v-update-docker-catalog`                                                                             | root           |

| `/home/<user>/apps/<slug>/`                                                                    | project dir: `compose.yaml` (rendered, `root:user 0640`), `.env` (`root:user 0640`, contains secrets), `app.conf` (**authoritative** record, `root:user 0640`), `data/` (volumes, `user:user`), `logs/` | mixed          |
| `/home/<user>/apps/<slug>/app.conf`                                                            | `SLUG VERSION IMAGE_DIGEST DOMAIN WEB_PORT EXTRA_PORTS STATUS TEMPLATE SUSPENDED TIME DATE` + `VAR_<NAME>='…'` for non-secret variables                                                                 | root:user      |
| `/usr/local/hestia/data/users/<user>/apps.conf` (**new**)                                      | index for listing, rebuilt from `app.conf` files by `v-rebuild-docker-apps`                                                                                                                             | root:user 0640 |
| `~/conf/web/<domain>/nginx.conf.tplvars`                                                       | `docker_port='30002'` via `v-change-web-domain-tplvar` ([09](./09-web-templates-metadata.md) §5)                                                                                                        | root:user      |
| `/usr/local/hestia/data/ports/<user>.conf`                                                     | `APP='docker:<slug>'` entries ([04](./04-port-registry.md))                                                                                                                                             | root           |
| `/usr/local/hestia/data/queue/apps.pipe` (**new**)                                             | queued installs/updates (`v-update-sys-queue apps`, cron `*/1`)                                                                                                                                         | root           |

Why `~/apps/` and not `~/web/<domain>/`: an app may later be re-bound to another domain, and upstream `v-backup-user` already archives every extra home directory, so `apps/` is backed up with **zero changes** to upstream (§5.6).

| ------------------------------------------ | ------------- | -------------------------------- | -------------------------------------------------------- |

### 5.3 Manifest schema (`docs/design/schemas/docker-app.schema.json`, validated in CI)

```yaml
# install/common/apps/docker/uptime-kuma/manifest.yaml
schema: 1
slug: uptime-kuma # [a-z0-9-]{2,32}, directory name, Compose project suffix
name: Uptime Kuma
summary: Self-hosted monitoring with status pages.
description: |
  Markdown. Shown on the detail page.
icon: icon.svg # file in the manifest dir
category: monitoring # monitoring | automation | dev | cms | storage | security | database | admin | other
homepage: https://github.com/louislam/uptime-kuma
license: MIT
version: "1.23.16" # app version; manifest version line
image: # primary image, pinned
  ref: louislam/uptime-kuma:1.23.16
  digest: sha256:… # required for shipped catalog; pull verifies it
  arch: [amd64, arm64]
admin_only: false # true → only admins may install (Portainer)
min_resources: { memory: 256M, disk: 1G, cpus: 0.25 }
limits_default: { memory: 512M, cpus: 0.5 } # capped by package DOCKER_MEMORY/DOCKER_CPUS
run_as_user: true # container runs as the hosting user's uid:gid (image supports it)
ports:
  web: { container: 3001, protocol: tcp, proxy_template: docker-proxy-ws } # exactly one 'web'
  # extra ports: name: { container, protocol, public_default: false, description }
volumes:
  - { name: data, path: /app/data } # bind-mounted from ~/apps/<slug>/data/<name>
variables:
  - name: TZ
    label: Time zone
    type: string # string | int | bool | enum | password | email | url | domain
    default: "{{server.timezone}}" # interpolations: server.timezone, domain, user, user.email, random(32)
    required: true
    validation: "^[A-Za-z_/+-]+$"
  - name: ADMIN_PASSWORD
    label: Initial admin password
    type: password
    secret: true # generated if blank, write-only in UI, masked everywhere
    default: "{{random(24)}}"
healthcheck: # used for STATUS and post-install wait
  http: { path: /, port: web, expect: 200, timeout: 90s }
post_install: |
  Open https://{{domain}} and create the first admin account.
hooks: # optional scripts in the manifest dir, run as root inside func/docker.sh guards
  pre_update: hooks/pre_update.sh # e.g. database dump into data/.dumps
  pre_backup: hooks/pre_backup.sh
  post_restore: hooks/post_restore.sh
forbidden_check: true # the renderer refuses privileged, cap_add, devices, host network, docker.sock, mounts outside data/
```

`compose.yaml.tpl` is a Compose file with `{{var}}` placeholders (`{{PORT_web}}`, `{{data.data}}`, `{{limits.memory}}`, `{{uid}}`, `{{gid}}`, variables by name). The renderer (`func/docker.sh:render_compose`) substitutes, injects `name: ap-<user>-<slug>`, `restart: unless-stopped`, logging limits (`json-file`, `max-size 10m`, `max-file 3`), `cpus`/`mem_limit`, `ports: ["127.0.0.1:{{PORT_web}}:3001"]` (or `0.0.0.0` only when the registry entry is `PUBLIC='yes'`), `user: "{{uid}}:{{gid}}"` when `run_as_user`, and then validates the result with `docker compose config` plus the forbidden-keys check.

### 5.6 Backups and restore

`v-backup-user` already archives `~/apps/` as a user directory. What ArcPanel adds:

- **Consistency:** an additive cron line runs `v-backup-docker-apps all` 15 minutes before the daily `v-backup-users` run (both times are in the `hestiaweb` crontab, so the upgrade script places it relative to the existing line). For UI-triggered backups, `BackupService::schedule()` calls `v-backup-docker-apps USER` before `v-schedule-user-backup`. `pre_backup` hooks dump databases into `data/.dumps/`; apps without a hook are paused for the copy window (seconds). The marker `data/.backup-ok` carries the timestamp so restores can tell a consistent snapshot from a crash-consistent one. Known limitation until E15: the CLI `v-backup-user` alone yields a crash-consistent copy — documented, and `v-check-sys-docker` warns if the marker is older than the last backup.
- **Exclusions:** the Backup Exclusions page gets a "Docker apps" section listing apps; excluding one writes `USER='apps/<slug>'` (upstream's `USER=` accepts paths and excludes directories with `--exclude=path/*`, as the code shows).
- **Restore:** `v-restore-user … UDIR` brings `~/apps/` back; a hook `post_restore_user.sh` (or the Laravel `BackupService::restore()` after the upstream call, when no hook exists) runs `v-rebuild-docker-apps USER`, which re-reads each `app.conf`, re-allocates ports (same port if free), re-renders Compose for the **recorded** `VERSION`/digest (so a restore does not silently upgrade), runs `post_restore` hooks (import dumps), and starts the apps. Partial restore of one app: `v-restore-docker-app USER BACKUP SLUG` (**new**) extracts only `apps/<slug>` from the `user_dir/apps.tar.*` member.
- **Restic (incremental):** `~/apps` is inside the home snapshot; `v-list-user-files-restic` lets File Manager v2 browse it; per-app restore uses the same rebuild path.

| ---------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `v-list-sys-packages`  | `[FORMAT]`       | catalog merged with installed state and update availability (`apt list --upgradable` / `snap refresh --list`), cached 1 h                                                                                                                                                                   |
| `v-add-sys-package`    | `SLUG [VERSION]` | validates slug exists in the whitelist, adds the apt source/key (sha-verified) or snap, `apt-get install` with `DEBIAN_FRONTEND=noninteractive` and the pin, runs `post_install`, records `system.conf`; enqueued through `apps.pipe` when called from the UI (`v-run-sys-package-install`) |
| `v-delete-sys-package` | `SLUG [purge]`   | refuses if a Docker app or a template in use declares the runtime (`requires.runtime` scan over `web.conf` templates + `apps.conf`) unless `force`; `post_remove`; apt/snap remove                                                                                                          |
| `v-update-sys-package` | `SLUG`           | upgrade within the pin; later driven by E33 policies                                                                                                                                                                                                                                        |
| `v-check-sys-packages` | —                | validates manifests (CI + upgrade)                                                                                                                                                                                                                                                          |

Initial whitelist: Python 3 + pipx, Go, OpenJDK 21, Redis, Memcached, FFmpeg, ImageMagick, Certbot DNS plugins (`python3-certbot-dns-cloudflare`, `-route53`). **Not** Node.js (per-user, [07](./07-node-platform.md)); a system Node is installed by upstream for the terminal only.

### 6.3 Relationship to templates

Template sidecars declare `requires.runtime` ([09](./09-web-templates-metadata.md) §4.2); the picker resolves each id against `provides` of installed system packages (`v-list-sys-packages`) and, for `node`, the user's runtimes. Missing runtimes show a badge with "Install" (admin, deep link to the System tab) or "ask your provider". `python-gunicorn`/`django` templates require `python3`; Docker-related templates require `docker` (`DOCKER_SYSTEM`).

### 6.4 UI

The store's **System** tab (admin only): same card grid; detail shows provider, source, pin, what depends on it (templates/apps); install/remove/update with the install log streamed (§6.5 target `system:<slug>` reading `data/apps/logs/<slug>.log`). Package edit is unaffected (system packages are server-wide).

### 6.5 Log streaming

Reuses the web terminal WebSocket `tail` control frame defined in [07](./07-node-platform.md) §6.4 with targets:

| Target                                                 | Effective-user files resolved by the server                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `docker:<slug>`                                        | `docker compose logs -f --no-color --timestamps` is **not** run as the user (no socket access); instead `v-run-docker-app-install`/lifecycle commands tee container logs into `/home/<user>/apps/<slug>/logs/app.log` through a root-side `docker compose logs -f` writer started by the lifecycle commands (one per running app, `logrotate`d). The ws server tails that file as the user — same ownership check as Node logs |
| `docker-task:<slug>:<task>` (task = install or update) | `~/apps/<slug>/logs/install.log` / `update.log`                                                                                                                                                                                                                                                                                                                                                                                |
| `system:<slug>`                                        | `/usr/local/hestia/data/apps/logs/<slug>.log`, allowed only when the effective user is `ROOT_USER` (the server already knows `ROOT_USER` from `v-list-sys-config`)                                                                                                                                                                                                                                                             |

Fallback without the web terminal: poll `v-list-docker-app-logs USER SLUG 200` every 3 s.

## 7. Failure modes

| Failure                                                             | Mitigation                                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Disk fills with images/volumes                                      | `DOCKER_DATA_ROOT` configurable; `v-check-sys-docker` prunes unreferenced images > 7 days and reports usage; app `data/` counts toward the user's `U_DISK` because it is in the home dir (upstream `v-update-user-disk` already measures home); `min_resources.disk` checked before install |
| Image pull fails / registry rate limit                              | install stays `failed` with the log; retry button; digest pinning means a tag re-push cannot change what runs; admins may set a registry mirror in `daemon.json` via `v-change-sys-docker-config` (**new**, key/value whitelist)                                                            |
| Port conflict                                                       | all ports from the registry; `v-check-user-port` before `up`; conflicts surfaced in "My ports"                                                                                                                                                                                              |
| Update with a breaking image                                        | `pre_update` dump + `PREV_IMAGE_DIGEST`; automatic rollback when the healthcheck fails; manual rollback button; catalog manifests carry `version` lines so a major jump is explicit                                                                                                         |
| Orphan containers (manual `docker` by an admin, crashed install)    | `v-check-sys-docker` lists containers without `ap-` project label or without `app.conf`; one-click remove on Server → Docker                                                                                                                                                                |
| User deleted                                                        | `post_delete_user.sh` hook: `v-delete-docker-app …` for each app (`compose down`), ports released; without a hook the nightly check removes projects whose user no longer exists (containers are stopped first, data left in `/home` for the admin's upstream cleanup)                      |
| Container runs as root inside, writes root-owned files into `data/` | `run_as_user` where images support it; otherwise `post_backup`/restore hooks `chown -R` to the user; documented per manifest                                                                                                                                                                |
| Catalog repo compromised                                            | signed tags/commits verified with the pinned key; schema validation; `forbidden_check`; a bad refresh never swaps the directory                                                                                                                                                             |
| Secrets in `.env`                                                   | `root:user 0640` (readable by the user — their own secrets), never in `app.conf`, masked in logs/UI, excluded from `v-dump-site` zips (not under `~/web`)                                                                                                                                   |
| Compose plugin or Docker apt repo unavailable on an OS              | `v-add-sys-docker` checks the OS matrix (Debian 12/13, Ubuntu 22.04/24.04/26.04) against Docker's published repos and fails early with a clear message                                                                                                                                      |

## 8. Testing

- **CI:** `v-check-docker-catalog` / `v-check-sys-packages` schema validation and `docker compose config` of every manifest with default variables; forbidden-key tests with crafted manifests.
- **BATS (`test/docker.bats`, Docker-in-VM job):** `v-add-sys-docker`; install Uptime Kuma on a domain → `curl` through NGINX returns 200, port registered, `app.conf` written, STATUS `running`; stop/start/restart; `v-change-docker-app-env` recreates; update to a newer manifest and rollback; backup (`v-backup-docker-apps` + `v-backup-user`) → delete app → restore → running on the same port with data intact; `v-delete-docker-app keep-data`; `v-add-sys-package redis` binds localhost; `v-delete-sys-package` refuses while a template uses it.
- **Pest:** `DockerAppService` argument shaping (vars via temp file), `DockerAppPolicy` matrix (package `DOCKER`, `admin_only`, tree), manifest-to-form generation, status polling state machine; `SystemPackageService` admin-only.
- **Playwright (roadmap metric):** a user installs n8n from the catalog, gets HTTPS on a domain (Let's Encrypt staging), sees live logs, removes it cleanly — no SSH; admin installs Redis from the System tab and the `requires` badge turns green on a template card; 5 users × 2 Docker apps + 2 Node apps with zero port conflicts (shared with [04](./04-port-registry.md) §11).

## 9. Open questions

1. Umami vs Plausible for the initial catalog — pick by memory footprint and licence at implementation time (Plausible CE needs ClickHouse: likely too heavy).
2. Should users be able to add **private** catalog sources (their own manifests)? Not in 2.0: it reopens the arbitrary-Compose risk; admins may point `DOCKER_CATALOG_URL` at a fork.
3. Per-app network isolation: one Compose network per project is the default (no cross-app traffic). Apps that must talk to another user's app (rare) are out of scope; apps talking to the user's own Node app use the registry port on `127.0.0.1` via `host-gateway`.
4. Docker containers are outside the user's cgroup slice; `cpus`/`mem_limit` per app approximate the package. Moving containers into `user-<uid>.slice` via `cgroup_parent` is possible with the root engine — evaluate in Q3 (it would make `MEMORY_LIMIT` a true per-tenant ceiling including containers).
