# E12 — Port registry — design

**Status:** Implemented (2026-10-05, see §13) · **Epic:** E12 · **Base design:** [04 Port registry](../../design/04-port-registry.md) · **Previous specs:** [E1-S1](./2026-10-05-001-e1-laravel-foundation-slice1-design.md), [E1-S2](./2026-10-05-002-e1-s2-dashboard-web-domains-design.md), [E11](./2026-10-05-003-e11-reseller-design.md) · **Roadmap:** [§3 E12](../../roadmap.md)

## 1. Summary

E12 adds a central port registry: one answer to "which ports may user X bind, and which of them are reachable from the internet?". Admins allocate ports and ranges to users and resellers, resellers pass parts of their pool to their customers, and users reserve ports for what they run and open them to the internet when their owner allows it. Later epics (E14 Node apps, E4 Docker apps) take their ports from the registry through `v-allocate-user-port`.

Design document 04 stays the reference. This spec records the decisions of the 2026-10-05 brainstorm, the scope of E12 and where it differs from 04.

## 2. Decisions taken in the brainstorm

| #   | Question                                   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --- | ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Scope                                      | **All of E12** (CLI, data model, policies, Admin, Reseller and User pages) in one spec, four milestones (§3), each a tested commit.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| D2  | Reseller pool model                        | **Physical pool.** Every port belongs to exactly one user. A reseller's pool is the set of unassigned entries (`APP=''`) in its own `data/ports/<reseller>.conf`. Sub-allocation moves entries (splitting a block when needed) to the customer's file with `v-change-user-port-owner`. Ports of a deleted customer go back to its owner's pool when the owner is a reseller, and are freed otherwise.                                                                                                                                                                                                                                                                                                            |
| D3  | What users may do                          | Users **reserve** ports from their own pool (`APP='manual'` with a comment, for what they run over SSH), **release** them, and **toggle public** on ports with `PUBLIC_OK='yes'`. Gives E12 value before E14 and E4 exist. Answers 04 §12 question 2.                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| D4  | Suspend, unsuspend, delete, package change | **Hooks in upstream commands.** New library `func/hooks.sh` with `run_arcpanel_hooks EVENT ARGS…`, which runs every executable in `$HESTIA/func/hooks.d/<event>/` in name order. `v-add-user`, `v-change-user-package`, `v-suspend-user`, `v-unsuspend-user` and `v-delete-user` each gain **two lines** (the include and the call, §6). A deliberate exception to the "additive only" rule, like E11 D10, to be sent upstream. A failing hook is logged and never fails the upstream command. Firewall rules close immediately whatever path suspends or deletes a user. E14 (stop pm2 on suspend) and E4 reuse the hooks. Differs from 04 §5, which relied on the panel's `UserService` and the nightly check. |
| D5  | Where the data lives                       | No `U_PORTS` in `user.conf`: upstream commands rewrite that file with a fixed key list (E11 D2). Port totals are computed when read. The package key `PORTS` lives in the E11 sidecar `data/packages/<package>.tenancy`. The public-capable flag is its own key `PUBLIC_OK`, not a `public-ok` word in `COMMENT`. Entries store the firewall rule id in `FW_RULE`. The `IP` key of 04 §4.1 is dropped: `v-add-firewall-rule` filters by source CIDR, not by destination address. Differs from 04 §4.1, §4.3, §4.4 and §6.                                                                                                                                                                                        |
| D6  | Meaning of `PORTS`                         | Integer, `unlimited` or `0` (default). For a user: the pool size allocated on creation and topped up on package change. `unlimited`: no pool check, `v-allocate-user-port` takes the next free port in the server range when the pool is empty. For a reseller: `PORTS` is the **total for its tree** and joins `TENANCY_QUOTA_KEYS`, so `v-check-reseller-quota` applies the E11 D7 formula with usage = ports held by the reseller + ports held by its customers. A package change never takes ports away; a user above its limit is reported, not trimmed.                                                                                                                                                    |
| D7  | Public ports and the firewall              | Only single ports can be public; range blocks cannot. Firewall rules are `ACCEPT 0.0.0.0/0 <port> <proto>` with the comment `arcpanel-port-<port>-<user>` (the comment validator in `func/main.sh` accepts only letters, digits, spaces and `._-`, so the `arcpanel:<user>:<port>` tag of 04 is not possible). `FW_RULE` is the authoritative link; the comment helps humans and the reconciliation. With `FIREWALL_SYSTEM` empty, `v-add-firewall-rule` refuses to run: the registry still stores `PUBLIC='yes'` with `FW_RULE=''`, the UI warns that every port is reachable, and `v-check-sys-ports repair` writes the missing rules once the firewall is enabled.                                            |
| D8  | UDP, IPv6, kernel enforcement              | UDP can be allocated; public UDP ports are firewall rules only (proxy templates are TCP). IPv6 and blocking binds at the kernel level are out of scope (04 §12 questions 1 and 3).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

## 4. Scope

### In scope

1. `func/ports.sh` and the commands of §5, the registry files, `hestia.conf` keys, package `PORTS`, `v-add-sys-port-registry`, the nightly reconciliation job.
2. `func/hooks.sh`, the hook directory and the five one-line changes of §6.
3. `PortService`, `PortRecord`, `PortPolicy`, new capabilities, navigation entries.
4. Admin → Server → Ports; `/app/ports` for resellers and users; `PORTS` in the Packages form; Ports card on the user detail page.
5. BATS, Pest, Vitest and Playwright tests; documentation updates of §12.

### Out of scope

- Consumers of the registry: Node apps (E14), Docker apps (E4) and their proxy templates (E6).
- Alerts on reconciliation findings (E16); E12 writes a notification only.
- IPv6, public rules bound to one destination IP, kernel-level bind enforcement (D8).
- Any change to the legacy `web/` app.

### Done when

- An admin allocates a block of 100 public-capable ports to a reseller.
- The reseller gives 10 of them to a customer; a package with `PORTS='5'` gives a new customer 5 ports on creation.
- The customer reserves a port, makes it public, and the firewall has exactly one rule tagged with that port; suspending the customer closes the rule, unsuspending reopens it, deleting the customer removes it and returns the ports to the reseller's pool.
- The reseller cannot give more ports than its package `PORTS` allows, and the error names `PORTS`.
- 5 users × 4 reservations in parallel produce 20 distinct ports and no conflict on Admin → Ports. (The roadmap metric with 20 Node and Docker apps runs when E14 and E4 ship.)

## 5. CLI and data model (M1)

### 5.1 Files

| File                               | Content                                                                                                                                                                                                                                                                      | Notes                                                                                                                                                                   |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `$HESTIA/data/ports/<user>.conf`   | one entry per line: `PORT` (`30001` or `30010-30019`), `PROTO` (`tcp`/`udp`), `APP` (`node:<domain>`, `docker:<app>`, `manual` or empty), `PUBLIC` (`yes`/`no`), `PUBLIC_OK` (`yes`/`no`), `FW_RULE` (rule id or empty), `COMMENT`, `SUSPENDED` (`yes`/`no`), `TIME`, `DATE` | `APP` kinds other than `manual` are owned by E14 and E4. Entries are kept sorted by port. Mode `640`, owner root                                                        |
| `$HESTIA/data/ports/reserved.conf` | owner-less entries in the same format, with `COMMENT` naming the reason (`panel`, `ssh`, `ftp-passive`, …)                                                                                                                                                                   | regenerated by `v-update-sys-ports-reserved`; admin entries with `APP='admin'` survive regeneration                                                                     |
| `$HESTIA/data/ports/.lock`         | `flock` target                                                                                                                                                                                                                                                               | every writer holds it around read, check and write                                                                                                                      |
| `$HESTIA/data/ports/.report.json`  | last result of `v-check-sys-ports`                                                                                                                                                                                                                                           | read by Admin → Ports                                                                                                                                                   |
| `$HESTIA/data/ports/.deleted/`     | `<user>-<date>.conf` copies of files of deleted users                                                                                                                                                                                                                        | kept for audit; never read by allocation                                                                                                                                |
| `data/packages/<package>.tenancy`  | new key `PORTS` (integer, `unlimited`, default `0`)                                                                                                                                                                                                                          | E11 sidecar; `v-change-package-tenancy` and `v-list-package-tenancy` accept and print it                                                                                |
| `hestia.conf`                      | `PORT_RANGE_START` (`30000`), `PORT_RANGE_END` (`39999`), `PORT_REGISTRY` (`yes`)                                                                                                                                                                                            | `PORT_REGISTRY='no'` makes `v-allocate-user-port` return any free port in the range without pool checks (admin escape hatch); `v-list-sys-config` prints the three keys |

Reserved ports: `BACKEND_PORT`, `WEB_TERMINAL_PORT`, the SSH port, 21 and the FTP passive range, 25, 53, 110, 143, 465, 587, 993, 995, 3306, 5432, 80, 443, 8080, 8443, and every socket already listening in the server range when `v-update-sys-ports-reserved` runs at install or upgrade time.

### 5.2 Library `func/ports.sh`

Helpers used by every command below: `ports_file USER`, `ports_lock` / `ports_unlock`, `ports_in_range PORT`, `ports_is_reserved PORT PROTO`, `ports_owner PORT PROTO` (scans all files; prints the user or nothing), `ports_split USER PORT` (rewrites a block `a-b` around `p` as `a-(p-1)`, `p`, `(p+1)-b`), `ports_merge USER` (joins adjacent unassigned entries with the same `PROTO`, `PUBLIC_OK` and empty `COMMENT`), `ports_count USER` (single ports + range sizes), `ports_tree_count RESELLER`, `ports_free_block SIZE PROTO` (first free contiguous block in the server range), `ports_fw_open USER PORT`, `ports_fw_close USER PORT`, `ports_live` (one `ss -Hltnup` pass: port, proto, bind address, uid). Values are written with the same quoting as `update_object_value`; keys are validated against a fixed list.

### 5.3 Commands (all new)

| Command                                                          | Behaviour                                                                                                                                                                                                                                                                                                                                                      |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `v-add-sys-port-registry`                                        | idempotent setup: `hestia.conf` defaults, `data/ports/`, `reserved.conf`, the nightly `v-check-sys-ports notify` line in the `hestiaweb` crontab (same `sed -i` method as `v-add-sys-tenancy`), the hook scripts of §6                                                                                                                                         |
| `v-update-sys-ports-reserved`                                    | regenerates `reserved.conf` from `hestia.conf`, service configs and live sockets                                                                                                                                                                                                                                                                               |
| `v-change-sys-port-range START END`                              | `START < END`, both in 1024–65535; refuses (`E_INUSE`, first port outside on stdout) when an allocated entry falls outside the new range                                                                                                                                                                                                                       |
| `v-add-user-port USER PORT\|RANGE [PROTO] [PUBLIC_OK] [COMMENT]` | admin allocation: inside the server range, not reserved, not held by anyone; writes an unassigned entry. Refuses a reseller's customer whose owner's tree would exceed the owner's `PORTS` (reseller quota)                                                                                                                                                    |
| `v-add-user-port-pool USER [SIZE]`                               | allocates one contiguous block of `SIZE` (default: missing ports up to the package `PORTS`). For a reseller's customer the block comes from the owner's pool (moved with `v-change-user-port-owner`), otherwise from the server range. `E_LIMIT` when no room                                                                                                  |
| `v-delete-user-port USER PORT\|RANGE [force]`                    | refuses an entry with `APP` set unless `force`; closes its firewall rule; returns the ports to the owner's pool (reseller) or frees them                                                                                                                                                                                                                       |
| `v-change-user-port-owner USER PORT\|RANGE NEW_USER`             | moves unassigned entries (splitting blocks) between any two users; refuses entries with `APP` set; checks the receiving reseller tree's `PORTS`. `PUBLIC_OK` is kept. Who may move what (reseller → own customer, customer → its reseller, admin → anyone) is decided by `PortPolicy`, the same trust model as every other command (04 §6)                     |
| `v-change-user-port-public-ok USER PORT\|RANGE yes\|no`          | sets the flag; turning it to `no` on a public port closes the port first                                                                                                                                                                                                                                                                                       |
| `v-allocate-user-port USER APP [PROTO] [PORT] [COMMENT]`         | **the API for E14 and E4, and the "Reserve" action** (`APP='manual'`). With `PORT`: that port must be unassigned in the user's pool. Without: the first unassigned port in the pool (splitting a block); when the pool is empty and `PORTS='unlimited'`, the next free port in the server range. Prints the port. `E_LIMIT` when the pool is empty and limited |
| `v-release-user-port USER APP\|PORT`                             | frees every entry whose `APP` matches (or the given port): closes the firewall rule, clears `APP`, `PUBLIC` and `COMMENT`, merges; the port stays in the user's pool                                                                                                                                                                                           |
| `v-change-user-port-public USER PORT yes\|no`                    | single assigned or unassigned port; `yes` needs `PUBLIC_OK='yes'` (`E_FORBIDEN`) and the user not suspended; opens or closes the firewall rule (D7)                                                                                                                                                                                                            |
| `v-check-user-port USER PORT [PROTO]`                            | exit `0` when `USER` holds `PORT` and no socket of another uid listens on it; used by E14 and E4 before a start                                                                                                                                                                                                                                                |
| `v-list-user-ports USER [FORMAT]`                                | the user's entries plus live state per port (`LISTEN`: `no`, `local` for 127.0.0.1/::1, `any` for 0.0.0.0/::) and the totals `ALLOCATED`, `ASSIGNED`, `PUBLIC`, `LIMIT`; formats `json`, `plain`, `csv`, `shell`                                                                                                                                               |
| `v-list-sys-ports [FORMAT] [orphans]`                            | every entry with owner, the reserved list, live sockets in the server range with owner resolution (uid → user) and the findings of §5.4; with `orphans`, findings only                                                                                                                                                                                         |
| `v-check-sys-ports [notify\|repair]`                             | reconciliation (§5.4); writes `.report.json`; `notify` sends one admin notification when findings exist; `repair` writes missing rules for public entries of active users and deletes tagged rules without a matching entry                                                                                                                                    |

Commands log through `log_event` and, for owner and public changes, `v-log-action` with category `Firewall` like the firewall commands.

### 5.4 Reconciliation findings

| Finding           | Meaning                                                                                 | Admin actions on the page                                                |
| ----------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `orphan-socket`   | a socket in the server range that no entry covers                                       | "Register to user" (`v-add-user-port` + `v-allocate-user-port … manual`) |
| `foreign-socket`  | a socket on an entry, owned by another uid                                              | none (informational)                                                     |
| `exposed-private` | a socket bound to all addresses on an entry with `PUBLIC='no'` while the firewall is on | none (the firewall blocks it); shown to the owner too                    |
| `missing-rule`    | `PUBLIC='yes'`, user active, `FW_RULE` empty or pointing at a missing rule              | "Repair"                                                                 |
| `stale-rule`      | a firewall rule tagged `arcpanel-port-` whose entry is gone, private or suspended       | "Close rule"                                                             |
| `unmanaged-rule`  | an `ACCEPT` rule on a port inside the server range without the tag                      | "Adopt" (links the rule to the entry)                                    |
| `orphan-file`     | `data/ports/<user>.conf` of a user that no longer exists                                | moved to `.deleted/` by `repair`                                         |
| `over-limit`      | a user or reseller tree holding more ports than its `PORTS`                             | none (never trimmed, D6)                                                 |

## 6. Hooks (M2)

`func/hooks.sh` defines `run_arcpanel_hooks EVENT ARGS…`. It runs each executable file in `$HESTIA/func/hooks.d/<EVENT>/` in name order with `ARGS`, logs a non-zero exit to `$HESTIA/log/system.log` and always returns `0`. Hook scripts must be idempotent.

| Upstream command        | Line added (at the end of the action section, before logging)    | Hook shipped by E12                                                                                                                                                                                                             |
| ----------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `v-add-user`            | `run_arcpanel_hooks post_add_user "$user"`                       | `post_add_user/50-ports`: `v-add-user-port-pool USER` when the package `PORTS` > 0                                                                                                                                              |
| `v-change-user-package` | `run_arcpanel_hooks post_change_user_package "$user" "$package"` | `post_change_user_package/50-ports`: tops the pool up to the new `PORTS`; never shrinks                                                                                                                                         |
| `v-suspend-user`        | `run_arcpanel_hooks post_suspend_user "$user"`                   | `post_suspend_user/50-ports`: closes every public rule, sets `SUSPENDED='yes'`, keeps `PUBLIC='yes'`                                                                                                                            |
| `v-unsuspend-user`      | `run_arcpanel_hooks post_unsuspend_user "$user"`                 | `post_unsuspend_user/50-ports`: reopens the rules of public entries, sets `SUSPENDED='no'`                                                                                                                                      |
| `v-delete-user`         | `run_arcpanel_hooks pre_delete_user "$user"` (before deletion)   | `pre_delete_user/50-ports`: closes rules, copies the file to `.deleted/`, returns the ports to the owner's pool or frees them. Runs before deletion because `tenancy.conf`, which names the owner, goes with the user directory |

The source line `source $HESTIA/func/hooks.sh` is added next to the other `func/` includes of the five commands, so each command has two changed lines in total. A pool allocation that fails in `post_add_user` (no room) is logged and the user is created without ports; the lazy path in `v-allocate-user-port` tries again on first use. The panel's wizard shows the failure from the `v-list-user-ports` totals.

## 7. Laravel side (M3, M4)

### 7.1 Services and records

- `App\Services\Ports\PortService`: `listForUser()`, `listSystem()`, `allocate()`, `reserve()`, `release()`, `setPublic()`, `setPublicOk()`, `subAllocate()`, `reclaim()`, `delete()`, `changeRange()`, `repair()`, `requestMore()`. Every method runs commands through `ArcCommand` with `Step` lists, like `UserService`.
- `App\Services\Ports\PortRecord` and `PortTotals`: typed rows from `v-list-user-ports json` and `v-list-sys-ports json`.
- `PackageService` and the package form read and write `PORTS` through `v-change-package-tenancy`.

### 7.2 Authorization

| Unit           | Change                                                                                                                                                                                                                                                                                                    |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Capabilities` | `ports.view` (admin All, reseller Tree, user Self), `ports.reserve` (OWN), `ports.public` (OWN, and reseller Tree), `ports.suballocate` (MANAGERS), `ports.allocate` (ADMIN), `server.ports` (ADMIN)                                                                                                      |
| `PortPolicy`   | `view`, `reserve`, `release`, `setPublic` (also requires `PUBLIC_OK='yes'` on the entry unless admin), `setPublicOk` (admin any; reseller only on its customers' entries and only to `no` unless the entry is already `yes`), `subAllocate` and `reclaim` (target in the tree), `allocate`, `changeRange` |
| Scoping        | objects outside the tree → 404 (E11 §10); `OwnerScope` gives the visible users                                                                                                                                                                                                                            |
| Navigation     | admin: "Ports" in the Server group; reseller and user: "Ports" in the "My hosting" group                                                                                                                                                                                                                  |

### 7.3 Admin → Server → Ports — `GET /app/server/ports`

- **Allocations tab:** data table per user (owner, role, allocated / limit, assigned, public); owner tree toggle (admin → resellers → customers); row detail lists the entries. Actions: "Allocate" dialog (user, range or count, protocol, public-capable, comment), delete, public-capable toggle, public toggle.
- **Live tab:** sockets in the server range with resolved owner and the findings of §5.4, each with its action. A banner when `FIREWALL_SYSTEM` is empty (D7).
- **Settings tab:** server range editor (refusal shows the first port outside), reserved list with add and delete of `APP='admin'` entries, `PORT_REGISTRY` switch with a warning.
- Routes: `GET /app/server/ports`, `POST /app/server/ports/allocate`, `POST /app/server/ports/range`, `POST /app/server/ports/reserved`, `DELETE /app/server/ports/reserved/{port}`, `POST /app/server/ports/repair`; per-entry actions share the routes of §7.4 under `{user}`.

### 7.4 Ports — `GET /app/ports` (user)

- Totals bar: allocated / limit, public count.
- Table: port or range, protocol, app, comment, public (toggle when `PUBLIC_OK`), live state, `exposed-private` warning.
- Actions: "Reserve a port" (first free or a chosen port, protocol, comment), "Release", public toggle, "Request more ports" (count and reason → `v-add-user-notification` to the owner: the reseller, or every admin through `ROOT_USER`).
- Routes: `POST /app/ports/{user}/reserve`, `POST /app/ports/{user}/{port}/release`, `POST /app/ports/{user}/{port}/public`, `POST /app/ports/{user}/{port}/public-ok`, `DELETE /app/ports/{user}/{port}`, `POST /app/ports/request`. `{port}` is a single port or a range `a-b`; `effective-user` and `not-readonly` middleware as in S2.

### 7.5 Ports — `GET /app/ports` (reseller)

- "My pool" section: total (tree held / `PORTS`), given to customers, free; the reseller's own entries with the user actions of §7.4.
- "Customers" section: per-customer allocated / assigned / public, expandable entries; "Give ports" dialog (customer, count or range from the free pool; count picks the first contiguous block); "Reclaim" on unassigned entries; public-capable toggle within D2 rules.
- Port requests from customers appear in the reseller's notification tray (no separate inbox).
- Route: `POST /app/ports/{user}/give` and `POST /app/ports/{user}/reclaim` for sub-allocation.

### 7.6 Packages

`PORTS` field in the package form (integer or unlimited) next to the E11 tenancy fields; the reseller quota bar includes `PORTS`; the packages list shows the column.

### 7.7 Users module

User detail gets a Ports card (allocated / limit, public count, link to the user's ports). The create wizard does not change: the `post_add_user` hook allocates the pool, and the summary step reports the allocated count.

## 8. Error handling

| Code         | Cause                                                                                                                  | Panel message                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `E_LIMIT`    | pool empty and limited; reseller tree over `PORTS`                                                                     | "No free ports left in your pool" with "Request more ports"; for resellers, names `PORTS` |
| `E_EXISTS`   | port held by another user                                                                                              | "Port N is already allocated"                                                             |
| `E_FORBIDEN` | outside the server range, reserved, public without `PUBLIC_OK`, suspended user                                         | the reason in one line                                                                    |
| `E_INUSE`    | `APP` set (delete or move without `force`); range change would drop allocations; foreign socket on `v-check-user-port` | names the app or the first port                                                           |
| `E_INVALID`  | bad port, range or protocol                                                                                            | field error                                                                               |

All writes hold `data/ports/.lock`. Firewall changes run after the registry write and inside the lock; when `v-add-firewall-rule` fails with the firewall on, the registry change is rolled back and the error is returned. Hook failures never fail the upstream command (§6). Objects outside the tree → 404; policy refusals inside the tree → 403.

## 9. Install, upgrade and development

- The installers and `test/dev-sync.sh` run `v-add-sys-port-registry` after `v-add-sys-tenancy`.
- The upgrade step of the next ArcPanel version (`install/upgrade/arcpanel/1.1.0.sh` while 1.1.0 is unreleased, otherwise a new file) runs it.
- `install/common/packages/reseller.tenancy` gains `PORTS='100'`; `default` stays at `0`.
- New commands are reachable through the existing sudoers rule of S1 (all of `bin/`).

## 11. Risks

| Risk                                                 | Mitigation                                                                                                                              |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Hook lines conflict on an upstream merge             | two lines per command, listed in the upstream-diff allowlist; BATS hook cases catch a lost line; upstream PR for a hook mechanism       |
| Firewall disabled, every port reachable              | banner on Admin → Ports and on public toggles; `repair` after enabling                                                                  |
| Users bind all addresses by hand                     | not blocked (non-goal of 04); shown as `exposed-private` to the admin and the owner                                                     |
| Restore does not bring back `data/ports/<user>.conf` | restored users get a fresh pool from the package through `v-add-user-port-pool` on first use; documented; a restore hook is a follow-up |
| `ss` output differs between distributions            | one parser in `ports_live`, covered by BATS on Debian 12 and Ubuntu 24.04                                                               |
| Concurrent writers outside the commands              | only commands write `data/ports/`; the panel never writes files directly                                                                |

## 13. Implementation notes (2026-10-05)

Decisions taken while building E12 that differ from, or add to, the sections above:

- **Firewall link (D7):** `v-delete-firewall-rule` renumbers every rule after a delete, so rule ids are never stored. The comment `arcpanel-port-<port>-<user>` is the link: rules are found, opened and closed by it, one lookup per delete. `FW_RULE` in the JSON output is the current id, looked up when the entries are read, and is not written to the files. Linking an unmanaged rule ("Link to …") gives it the tag with `v-change-firewall-rule` (`v-change-user-port-public USER PORT yes RULE`; the rule must be on the same port).
- **Protocols:** a port number belongs to one user for both protocols. `PROTO` names the protocol an assigned port is used with (firewall rule, live check); free entries are `tcp`. `v-add-user-port` has no `PROTO` argument.
- **Public ports:** only assigned single ports can be public; releasing a port closes it. Admin → Ports allows public use first ("Allow public use"), then opens the port.
- **Reserved list:** `data/ports/.reserved.conf`, a hidden file, so that a user named `reserved` cannot collide with it. Entries are `APP='system'` (rewritten by `v-update-sys-ports-reserved`), `admin` (`v-add-sys-port-reserved`, `v-delete-sys-port-reserved`) or `listening` (sockets found at the first setup).
- **Merging:** adjacent free entries with the same `PUBLIC_OK` and `SUSPENDED` merge; the first comment is kept.
- **Reseller PORTS (D6):** the tree's **use** is checked: the ports its customers hold plus the reseller's own assigned ports; its free pool does not count. `v-check-reseller-quota` and the owner change apply it through `ports_quota_check`. A physical allocation into a tree (`v-add-user-port`, `v-add-user-port-pool`, a move from outside the tree) checks the tree's total against `PORTS`. `over-limit` findings exist only for reseller trees and resellers' customers; administrators may give root-owned users more than their package says.
- **Pools of customers:** `v-add-reseller-user` runs `v-add-user` with `ARC_PORTS_DEFER=yes`, so the `post_add_user` hook skips it, and allocates the pool from the reseller once the owner is set. A reseller that gives more ports than its free pool (`+COUNT`) is topped up from the server range while its tree has room; a reseller made with `v-change-user-role` therefore needs no allocation before it gives ports.
- **Commands added to §5.3:** `v-add-sys-port-reserved`, `v-delete-sys-port-reserved`, and the hook back ends `v-suspend-user-ports`, `v-unsuspend-user-ports`, `v-delete-user-ports`. `v-add-user-port-pool` takes `[PUBLIC_OK]` for blocks from the server range. `v-change-user-port-owner` takes `+COUNT` for the lowest free ports.
- **Hooks:** scripts run with `bash` (`func/` files are not executable on a server synced by `test/dev-sync.sh`). There is no upstream-diff CI check yet (E8/E10); the five changed commands are listed in [01](../../design/01-architecture-overview.md) §3.2.
- **Findings:** `foreign-socket` ignores root-owned sockets (the Docker proxy of E4 runs as root).
- **Panel:** the owner tree of Admin → Ports is the indented account table. The `PORT_REGISTRY` switch is shown as a warning when off and changed with `v-change-sys-config-value`; it has no switch on the page. "Request more ports" sends a notification to the owner (`ROOT_USER` for users without a reseller). The give dialog binds its customer with inline Alpine, so there is no new Alpine module and no Vitest case.
- **Tests:** BATS `test/arcpanel-ports.bats` (22 cases, including 20 parallel allocations for one user and every hook) and `test/arcpanel-tenancy.bats` (20) pass on `arcpanel-test`; Pest 259 tests pass; Playwright 21 tests pass, with `test/e2e/ports.spec.js` and Lighthouse accessibility 100 on both Ports pages. The upstream `test.bats` passed 248 of 255: the 7 IP tests fail because `/run/sshd` is missing in the WSL distribution (2 of them, netplan, failed before E12 too). The roadmap's 20 Node and Docker apps across 5 users waits for E14 and E4.
- **e2e helper:** `login()` leaves the page before it clears the cookies, so a request still running cannot bring back the previous session.
- **REST API v2 (2026-10-08):** a user's ports and the registry are also reachable under `/api/v2/users/{user}/ports` and `/api/v2/system/ports` (permission sets `v2-apps` and `v2-server`), on the same `plan*` steps of `PortService`; the range parsing, owner lookups and flash results of both controllers moved into `PortActions`. See the [E34 batch 4 spec](./2026-10-08-002-e34-api-v2-batch4-design.md) §4.5.
