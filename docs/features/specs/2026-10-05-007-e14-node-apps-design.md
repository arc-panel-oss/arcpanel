# E14 — Node Apps with pm2 — design

**Status:** Implemented (2026-10-05, see §13) · **Epic:** E14 · **Base design:** [07 Node platform](../../design/07-node-platform.md) §5–§7 · **Previous specs:** [E12](./2026-10-05-004-e12-port-registry-design.md), [E6 batch 1](./2026-10-05-005-e6-templates-batch1-design.md), [E13](./2026-10-05-006-e13-node-manager-design.md) · **ADRs:** [0005 pm2 process model](../../adr/0005-pm2-process-model.md), [0001 view layer](../../adr/0001-view-layer.md) · **Roadmap:** [§3 E14](../../roadmap.md)

## 1. Summary

E14 turns a web domain into a Node.js app. The panel allocates a port from the user's pool (E12), switches the domain to one of the Node templates of E6 batch 1 with that port, writes a pm2 ecosystem file and starts the app in a pm2 daemon that belongs to the user and runs under `systemd --user`, so it comes back after a reboot. Users manage apps from a new Node apps page: create wizard, live status, logs, environment, settings, install and build. Suspend, delete, rebuild, backup and restore keep apps consistent without new changes to upstream commands.

Design document 07 §5–§7 stays the reference. This spec records the decisions of the 2026-10-05 brainstorm, the scope of E14 and where it differs from 07.

## 2. Decisions taken in the brainstorm

| #   | Question                    | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --- | --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Scope                       | **All of E14 except Git deploy and WebSocket logs**, in one spec with five milestones (§3). Git deploy and deploy keys move to E20; log streaming over the web terminal WebSocket moves to E18.                                                                                                                                                                                                                                                                                                                   |
| D2  | Process model               | **ADR-0005 option A**, now accepted: one pm2 daemon per user under `systemd --user`, linger enabled only while the user has at least one app. The unit is rendered by ArcPanel from its own template (same shape as pm2's `systemd` startup template); the output of `pm2 startup` is never parsed.                                                                                                                                                                                                               |
| D3  | Runtime of the daemon       | **pm2 lives in the user's default runtime** at the time the first app is created; that runtime is recorded as `PM2_RUNTIME`. pm2 is installed with a version pinned in `func/nodeapp.sh` when absent. Every app picks its own runtime through pm2's `interpreter`. `v-delete-user-node-version` refuses (`E_INUSE`) a runtime that is `PM2_RUNTIME` or used by an app.                                                                                                                                            |
| D4  | Where the app record lives  | **`data/users/<user>/nodeapps.conf`** (root, Hestia flat-file style) is authoritative. A copy, `~/web/<domain>/nodeapp/app.conf`, travels with the domain directory in backups and is read only by `v-rebuild-node-apps`, which validates every field again (format, path inside the home directory, port in the owner's pool, runtime installed). Differs from 07 §5.1, where `app.conf` is authoritative: the domain directory is writable by the user.                                                         |
| D5  | Restore, rebuild and reboot | **No new upstream changes.** Suspend, unsuspend and delete use the existing hook points of E12 D4. A new `v-check-sys-node`, run every 5 minutes from cron, imports restored apps (an `app.conf` without a record), stops daemons of suspended users, disables lingers of users without apps and marks apps whose runtime is gone. The panel calls `v-rebuild-node-apps` after its own rebuild and restore actions once those pages exist (E7). Differs from 07 §7 (hooks in `v-rebuild-user` and `v-restore-*`). |
| D6  | Start command               | **A file or a `package.json` script.** `START` is a path relative to `CWD` (`server.js`) or `npm:<script>` (`npm:start`, needed for `next start` and `nuxt start`). The wizard proposes one from `package.json` (`scripts.start`, then `main`, then `server.js`, `app.js`, `index.js`).                                                                                                                                                                                                                           |
| D7  | Logs in the panel           | **Polling** `v-list-node-app-logs` every 2 s with a byte offset, reusing the task poller of E13. No WebSocket in E14 (07 §6.4 moves to E18).                                                                                                                                                                                                                                                                                                                                                                      |
| D8  | Log rotation                | **One `logrotate(8)` file per user** (`/etc/logrotate.d/arcpanel-node-<user>`, `su <user> <user>`, `copytruncate`, 10 MB × 5). No `pm2-logrotate` module, no extra process. Answers 07 §10 question 1.                                                                                                                                                                                                                                                                                                            |
| D9  | Install and build           | **E13 task runner** with two new actions, `app-install DOMAIN` and `app-build DOMAIN [SCRIPT]`. The install command follows the lockfile: `pnpm-lock.yaml` → `pnpm install --frozen-lockfile`, `yarn.lock` → `yarn install --frozen-lockfile` (Yarn 1) or `--immutable` (Berry), `package-lock.json` → `npm ci`, none → `npm install`. One Node task per user at a time.                                                                                                                                          |
| D10 | Package keys and limits     | `NODE_APPS` in the package sidecar: default `3`, `developer` package `10`, `unlimited` allowed; a reseller's own package cannot exceed the reseller's. Server key `NODE_MAX_INSTANCES` in `hestia.conf` (default: `nproc`). Default memory per app: min(512 MB, `MEMORY_LIMIT` ÷ `NODE_APPS`), at most `MEMORY_LIMIT` when the package has one.                                                                                                                                                                   |
| D11 | Template after deletion     | The template of the domain before the app was created is stored in `PREV_TPL` and restored when the app is deleted. Differs from 07 §5.2 (back to `default`).                                                                                                                                                                                                                                                                                                                                                     |
| D12 | Pages                       | Node apps list, create wizard and app page (Overview, Logs, Environment, Settings, Danger zone); a Dashboard card; a "Node apps" tab on the user detail page (customer detail for resellers). Routes follow E13: `/app/node/{user}/apps`, `/app/node/{user}/apps/create`, `/app/node/{user}/apps/{domain}`.                                                                                                                                                                                                       |
| D13 | Environment                 | The panel sends `.env` through a `Secret` temp file. The page masks values with a per-value reveal. `PORT`, `HOST` and `NODE_ENV` cannot be set. `.env` is `0600`, owned by the user, and never appears in logs or audit entries.                                                                                                                                                                                                                                                                                 |

Also recorded: worker apps without a port (07 §10 question 3) are out of scope, but an empty `PORT` is valid in the data model; apps run under `systemd --user`, which is outside the SSH jail, at the same trust level as cron jobs (documented).

## 4. Scope

### In scope

1. `func/nodeapp.sh` and the commands of §5; the per-user pm2 daemon; the logrotate files; the `v-check-sys-node` cron line written by `v-add-sys-node`.
2. Package key `NODE_APPS` (sidecar, reseller check, `developer.tenancy`), server key `NODE_MAX_INSTANCES`.
3. Two task actions in the E13 runner; the in-use check in `v-delete-user-node-version`.
4. Hooks `60-nodeapps.sh` for `post_suspend_user`, `post_unsuspend_user` and `pre_delete_user`.
5. `NodeAppService`, records, policy abilities, capabilities, routes, navigation entry, `NODE_APPS` in the Packages form.
6. The `node-apps` island, the Dashboard card and the user detail tab.
7. BATS, Pest, Vitest and Playwright tests; the documentation changes of §12.

### Out of scope

- Git deploy, deploy keys, `v-add-node-app-git`, `v-run-node-app-deploy` (E20).
- Log streaming over the web terminal WebSocket (E18).
- Worker apps without a port, Python or other runtimes.
- The `pm2-logrotate` module; pm2 cluster metrics beyond `pm2 jlist`.
- Admin Server → Services "User daemons" row (07 §6.3): the Services page is legacy and moves in E7; `v-check-sys-node json` already reports the numbers.
- Any change to the legacy `web/` app or to upstream commands.

### Done when

1. A user on the `developer` package creates an Express app and a Next.js app on two domains from the wizard, runs "Install dependencies" and "Run build", and both answer over HTTPS within 5 minutes of starting the wizard.
2. The list shows both apps online with CPU, memory, restarts and uptime; the app page shows live logs and the environment editor saves a value that the app reads after the restart.
3. After the test distribution restarts, both apps answer again without anyone logging in.
4. After backup → delete user → restore, and after `v-rebuild-user`, the apps are online on the same ports within 5 minutes.
5. Suspending the user stops the apps and the daemon; unsuspending brings them back.
6. A reseller sees the apps of its customers and gets 404 for another tree; a user on the `default` package has no Node apps entry and the routes answer 403; a fourth app with `NODE_APPS='3'` fails with `E_LIMIT` and the page says why.
7. Deleting an app frees its port, restores the previous template and, for the last app, disables the daemon and linger.

## 5. CLI and data model (M1–M3)

### 5.1 Files

| Location                                      | Content                                                                                                                                                                                                                   | Owner and mode    |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| `$HESTIA/data/users/<user>/nodeapps.conf`     | one line per app: `DOMAIN NAME START CWD NODE_VERSION PORT INSTANCES MAX_MEMORY TEMPLATE PREV_TPL SUSPENDED TIME DATE` (`TEMPLATE` = Node template in use, `PREV_TPL` = template before the app)                          | root, `0640`      |
| `$HESTIA/data/users/<user>/pm2.conf`          | `PM2_RUNTIME`, `PM2_VERSION`                                                                                                                                                                                              | root, `0640`      |
| `~/web/<domain>/nodeapp/app.conf`             | copy of the app's line for backups (D4)                                                                                                                                                                                   | root:user, `0640` |
| `~/web/<domain>/nodeapp/ecosystem.config.cjs` | generated; `name`, `script`, `args`, `cwd`, `interpreter`, `env` (`.env` values, then `PORT`, `HOST=127.0.0.1`, `NODE_ENV=production`), `instances`, `exec_mode`, `max_memory_restart`, restart policy, log files, `time` | user, `0640`      |
| `~/web/<domain>/nodeapp/.env`                 | user environment, `KEY=value` lines                                                                                                                                                                                       | user, `0600`      |
| `~/web/<domain>/nodeapp/logs/`                | `out.log`, `err.log` (pm2), `install.log`, `build.log` (tasks)                                                                                                                                                            | user              |
| `~/.config/systemd/user/arcpanel-pm2.service` | rendered from `install/common/node/arcpanel-pm2.service`                                                                                                                                                                  | user, `0644`      |
| `~/.pm2/`                                     | pm2 home (`PM2_HOME`), `dump.pm2` written by `pm2 save`                                                                                                                                                                   | user              |
| `/var/lib/systemd/linger/<user>`              | `loginctl enable-linger` while the user has apps                                                                                                                                                                          | systemd           |
| `/etc/logrotate.d/arcpanel-node-<user>`       | D8                                                                                                                                                                                                                        | root, `0644`      |
| `data/packages/<package>.tenancy`             | `NODE_APPS` (integer or `unlimited`, default `3`)                                                                                                                                                                         | E11 sidecar       |
| `hestia.conf`                                 | `NODE_MAX_INSTANCES` (optional, default `nproc`)                                                                                                                                                                          | read only         |
| `data/ports/<user>.conf`                      | `APP='node:<domain>'` for the app's port                                                                                                                                                                                  | E12               |
| `~/conf/web/<domain>/nginx.conf.tplvars`      | `BACKEND_PORT` (E6)                                                                                                                                                                                                       | E6                |

`NAME` is the pm2 process name: `^[a-z0-9][a-z0-9._-]{0,39}$`, unique per user, default derived from the domain. `CWD` is relative to `~/web/<domain>/` (default `public_html`). `NODE_VERSION` is an installed version (`X.Y.Z`) or `default`.

### 5.2 Library `func/nodeapp.sh`

Sources `func/node.sh`. Record access (`nodeapp_get USER DOMAIN KEY`, `nodeapp_set`, `nodeapp_lines`, `nodeapp_count`) under `data/users/<user>/nodeapps.lock`; validation (`nodeapp_name_valid`, `nodeapp_start_valid`, `nodeapp_cwd_check` with the path-escape check of `func/node.sh`); `nodeapp_limit_check` (`NODE_APPS`); `nodeapp_runtime USER VERSION` (resolves `default`); `nodeapp_ecosystem_write`; `nodeapp_copy_write` (`app.conf`); daemon helpers `nodeapp_pm2_ensure` (pm2 installed, `pm2.conf`, unit, linger, `enable --now`), `nodeapp_pm2 USER ARGS…` (pm2 as the user with `PM2_HOME`, the `PM2_RUNTIME` first in `PATH`), `nodeapp_pm2_retire` (last app gone: stop and disable the unit, `pm2 kill`, disable linger, remove the logrotate file); `nodeapp_logrotate_write`; `nodeapp_template_for` (template kind and name per stack, through `arc_tpl_active_kind`).

### 5.3 The daemon

- `nodeapp_pm2_ensure USER` runs on every add, start and rebuild and is idempotent: it installs `pm2@<pinned>` into the default runtime when no runtime has it (synchronously, 15-minute timeout, as in `v-add-user-npm-package`), writes `pm2.conf`, renders the unit, runs `loginctl enable-linger USER`, waits for `user@<uid>.service`, then `systemctl --user --machine=USER@ daemon-reload` and `enable --now arcpanel-pm2`.
- The unit: `Type=forking`, `Environment=PM2_HOME=%h/.pm2 PATH=<runtime>/bin:/usr/bin:/bin`, `PIDFile=%h/.pm2/pm2.pid`, `ExecStart=<pm2> resurrect`, `ExecReload=<pm2> reload all`, `ExecStop=<pm2> kill`, `Restart=on-failure`, `RestartSec=5`, `WantedBy=default.target`.
- Every change to the app list ends with `pm2 save`, so `resurrect` brings back exactly the running set; stopped apps are saved as stopped.
- `nodeapp_pm2_retire USER` runs when the last app is deleted or the user is deleted.

### 5.4 Core commands (M1, all new)

### 5.5 Lifecycle and settings (M2, all new)

| Command                                                                                        | Behaviour                                                                                                                                                                                                                                                                                                      |
| ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `v-start-node-app`, `v-stop-node-app`, `v-restart-node-app`, `v-reload-node-app` `USER DOMAIN` | pm2 verbs as the user, then `pm2 save`. Start checks that the port is not held by another process (`E_INUSE` with the pid from `ss -ltnp`) and regenerates the ecosystem; `reload` is zero-downtime in cluster mode                                                                                            |
| `v-change-node-app-start USER DOMAIN START [CWD]`                                              | validates as add; rewrites record, copy and ecosystem; restarts a running app                                                                                                                                                                                                                                  |

| `v-change-node-app-scale USER DOMAIN INSTANCES [MAX_MEMORY]`                                   | `INSTANCES` 1 … `NODE_MAX_INSTANCES`; `MAX_MEMORY` in MB, 64 … `MEMORY_LIMIT` (or 8192 without a limit); `pm2 delete` and start again because `exec_mode` may change                                                                                                                                           |
| `v-change-node-app-env USER DOMAIN FILE`                                                       | `FILE` holds `KEY=value` lines (`KEY` `^[A-Za-z_][A-Za-z0-9_]*$`, no `PORT`, `HOST`, `NODE_ENV`, at most 200 lines and 64 KB); replaces `.env` as the user, regenerates the ecosystem, restarts a running app; the file is removed                                                                             |
| `v-list-node-app-env USER DOMAIN [FORMAT]`                                                     | `KEY`, `VALUE` rows read as the user; `log_event` records the command without values                                                                                                                                                                                                                           |
| `v-list-node-app-logs USER DOMAIN [STREAM] [OFFSET] [LINES] [FORMAT]`                          | `STREAM` `out`, `err`, `install` or `build`; without `OFFSET`, the last `LINES` (default 200, maximum 1000) lines; with `OFFSET`, the bytes after it (at most 256 KB); returns `LINES` and the next `OFFSET`; an offset beyond the file size (rotation) restarts at 0                                          |
| task actions `app-install DOMAIN`, `app-build DOMAIN [SCRIPT]`                                 | added to `v-start-user-node-task` and `v-run-user-node-task`; run as the user in `CWD` with the app's runtime first in `PATH`, `nice`, `ionice`, 15-minute timeout; output to `nodeapp/logs/install.log` or `build.log` and the task log; `app-build` defaults to `build` and reloads the app when it succeeds |

### 5.6 Persistence and convergence (M3)

| Unit                                                       | Behaviour                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `v-suspend-node-app`, `v-unsuspend-node-app` `USER DOMAIN` | stop + `SUSPENDED='yes'` and back; ports stay assigned                                                                                                                                                                                                                                                                                                                       |
| `v-suspend-user-node-apps USER`                            | hook back end for `post_suspend_user`: stops every app, sets `SUSPENDED='user'` where it was `no`, stops the unit                                                                                                                                                                                                                                                            |
| `v-unsuspend-user-node-apps USER`                          | hook back end for `post_unsuspend_user`: starts the unit, unsuspends the apps with `SUSPENDED='user'`; `SUSPENDED` is `no`, `yes` (the app itself) or `user` (set by the user suspension), so an app suspended on its own stays suspended                                                                                                                                    |
| `v-delete-user-node-apps USER`                             | hook back end for `pre_delete_user`: deletes every app (keep-files, the home directory goes anyway), retires the daemon                                                                                                                                                                                                                                                      |
| `v-rebuild-node-apps USER`                                 | imports `app.conf` copies that have no record (validated as D4; invalid copies are skipped and logged), re-registers ports (same port when free, otherwise a new one and `BACKEND_PORT` rewritten), re-renders ecosystem, unit, variables and logrotate file, installs a missing runtime from the cache when `NODE='yes'`, `pm2 resurrect`, then starts apps that should run |
| `v-check-sys-node [repair] [FORMAT]`                       | per user with records or copies: `import` (copy without record), `daemon-suspended`, `linger-orphan`, `runtime-missing`, `over-limit`; `repair` fixes the first four (rebuild, stop, disable, mark `errored` with a reason); JSON totals `USERS`, `DAEMONS`, `APPS`, `MEMORY`. Cron every 5 minutes with `repair`                                                            |
| `v-delete-user-node-version`                               | refuses with `E_INUSE` when the version is `PM2_RUNTIME` or the runtime of an app (resolved, so `default` counts)                                                                                                                                                                                                                                                            |
| `v-delete-user-nvm`                                        | refuses with `E_INUSE` while the user has apps                                                                                                                                                                                                                                                                                                                               |
| `v-add-sys-node`                                           | also writes the `v-check-sys-node repair` cron line and `NODE_APPS='10'` in `developer.tenancy` when absent                                                                                                                                                                                                                                                                  |

Every command validates with `is_format_valid` / `is_object_valid`, honours demo mode, logs with `log_event`, and changes add `v-log-action` with category `Node.js`.

## 7. Node apps pages (M5)

- **Island `node-apps`**, mounted on the three pages with a `view` prop; uses the shared `ApDialog`, `ApBadge`, `ApIcon`, `strings.js` and `task-poller.js` of E13.
- **List:** domain (link to the URL with an SSL badge), name, runtime, status pill, CPU, memory, restarts, uptime; row actions and bulk start, stop and restart; "Create app" disabled with the reason at the limit; empty state that links to the Node.js page when no runtime is installed. Polls the list every 10 s.
- **Wizard:** domain → start command (proposal from `package.json`, file or script) → runtime (installed versions, default selected) → port (automatic; advanced: a free port of "My ports") → template (Node templates with metadata, proposal from dependencies: `next` → `nextjs`, `nuxt` → `nuxt`, `@strapi/strapi` → `strapi`, `ws` or `socket.io` → `nodejs-proxy-ws`) → create. The result step offers "Install dependencies" and "Run build".
- **App page:** header with status, URL and actions. Tabs: **Overview** (port, runtime, template, instances, memory, pm2 stats, task panel for install and build), **Logs** (out, err, install, build; poll every 2 s with the offset; pause, clear view, download the last 1000 lines), **Environment** (key/value rows, masked values with a reveal per row, add, remove, save), **Settings** (start command, working directory, runtime, instances, memory), **Danger zone** (delete, with "keep files").
- **Dashboard card:** "Node apps: n online · m stopped · k errored" for accounts with `viewApps`, linking to the list.
- **User detail:** the user detail page (customer detail for resellers, `users/show`) gets a "Node apps" tab that renders the list for that account.
- Read-only state when the session is read-only or the package has `NODE='no'`. The pages render the list on the server too, so they read without scripts.

## 8. Error handling

| Code         | Cause                                                                                    | Panel message                                                     |
| ------------ | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `E_DISABLED` | package has `NODE='no'`                                                                  | "Node.js is not included in your package"                         |

| `E_INVALID`  | bad name, start command, environment line or template                                    | field error                                                       |
| `E_RESTART`  | NGINX refused the configuration; the daemon did not start                                | "The app was not created" with the reason; nothing is left behind |

## 11. Risks

| Risk                                                      | Mitigation                                                                                                                                                            |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `user@<uid>.service` not up right after `enable-linger`   | `nodeapp_pm2_ensure` waits up to 10 s for the user manager and its bus socket before calling `systemctl --user`                                                       |
| Many users with apps → many daemons                       | daemons only for users with apps, lingers removed with the last app, `v-check-sys-node json` reports daemon count and memory                                          |
| The user edits `ecosystem.config.cjs` or `app.conf`       | the ecosystem is regenerated on every start; `app.conf` is only an import source and is validated (D4)                                                                |
| The app binds `0.0.0.0` instead of `HOST`                 | nothing routes to it from outside (no firewall rule); `v-check-sys-ports` flags the socket; documented                                                                |
| A restore through the CLI leaves apps stopped for a while | `v-check-sys-node repair` runs every 5 minutes (D5)                                                                                                                   |
| pm2 installation needs the npm registry                   | the first app fails with `E_CONNECT` naming the registry; later apps reuse the installed pm2                                                                          |
| `.env` values in logs                                     | values only travel in temp files and `json` output read by the panel; `ArcCommand` masks the temp file; `log_event` records the command line without the file content |

## 13. Implementation notes (2026-10-05)

These notes win over the sections above where they differ.

1. **`app.conf` copy (D4, §5.1).** The copy is written by the user (`0640`), not root: the folder belongs to the user, so a root write could follow a symlink the user planted. It is refreshed with every record change and only read by `v-rebuild-node-apps`, which validates every field again.
2. **`STATE` key (§5.1).** Records have `STATE` (`running` or `stopped`) next to `SUSPENDED`, so an app stopped by the user stays stopped through a reboot, a rebuild, an unsuspension and the 5-minute check. `SUSPENDED` is `no`, `yes` (the app) or `user` (set by the user suspension).
3. **Daemon (§5.3).** The unit is `~/.config/systemd/user/arcpanel-pm2.service` (not `pm2-<user>.service`), rendered from `install/common/node/arcpanel-pm2.service` with `Type=forking`, `pm2 resurrect` and `pm2 kill`; an empty `~/.pm2/dump.pm2` is written first so that `resurrect` starts the daemon. `systemctl --user` runs as the user with `XDG_RUNTIME_DIR` instead of `--machine=USER@`. The pm2 client is never called while the daemon is down, because it would start a daemon outside systemd. pm2 `7.0.4` is pinned in `func/nodeapp.sh`. A suspended user's unit is disabled, so it does not start at boot.
4. **Ports on restore (§5.6).** `v-rebuild-node-apps` first keeps every port that can be kept, then gives new ports to the rest, so two restored apps never swap ports (a restore reorders `web.conf`). A restored user has no pool: the recorded port is put back with `v-add-user-port USER PORT no restored` when nobody holds it. A domain rendered before its port was registered again (it serves the "not configured" page) is rebuilt.
5. **Environment (§5.5, D13).** `PATH` is refused too, because the panel sets it. The command does not remove `FILE`; `ArcCommand` removes its temp files itself.
6. **Install and build (§5.5).** A successful install restarts an app that should run (it loads the new modules); a successful build reloads it, or starts it when it is not online (a Next.js app cannot start before its first build).
7. **A deleted web domain.** Upstream `v-delete-web-domain` has no hook. The panel's delete action runs `v-delete-node-app` after it, and `v-check-sys-node` reports `domain-missing` and removes the process, the port and the record of a domain deleted on the CLI.
8. **Routes (§6.3).** The navigation entry is `/node-apps`, which redirects to `/node/{user}/apps`: `/node/apps` would be the Node.js page of a user named `apps`. The Node.js entry is active on `node.show` only, so the two entries are not active together.
9. **Policy (§6.2).** `viewApps` is the capability and the scope; the navigation entry follows the package key like the Node.js entry (administrators always see it). Stop and delete need `removeApps` only, every other change `manageApps` (`NODE='yes'`).
10. **Pages (§7).** The user detail page has cards, not tabs, so the "Node apps" tab is a card that lists the account's apps and links to the list. The island's HTTP helper keeps the message and the field errors of a 422 answer, so the wizard shows validation errors at their fields.
11. **Done when 3.** Checked by terminating the WSL distribution (`wsl --terminate arcpanel-test`) and starting it again: both apps answered on their ports with an uptime of a few seconds, started by `user@<uid>.service` through linger, without a login.
12. **Root-owned homes (fix, 2026-10-06).** A user with a `nologin` shell has an SFTP jail and a root-owned home, so the user could not create `~/.pm2`. `nodeapp_unit_write` creates `~/.config` and `~/.pm2` with `node_home_dir_add` (E13 implementation notes) and the start fails with a message when it cannot. `test/arcpanel-nodeapps.bats` runs an app for a `nologin` user.
13. **Tests.** On `arcpanel-test` (Ubuntu 24.04, x64, NGINX + Apache): BATS `test/arcpanel-nodeapps.bats` 25 of 25, and with `arcpanel-node.bats`, `arcpanel-ports.bats`, `arcpanel-templates.bats` and `arcpanel-tenancy.bats` 121 of 121; Pest 327; Vitest 139; Playwright 30 of 30 with `test/e2e/node-apps.spec.js` (Done when 1, 2, 6 and 7 on `arce2edev`: Express and Next.js apps created from the wizard, dependencies installed, Next.js built, both answering over HTTPS with a self-signed certificate, each well under 5 minutes; live logs; an environment value read by the app; axe on the three pages; two `accessibility.spec.js` cases failed once with `ERR_CONNECTION_CLOSED` and passed on the rerun). Done when 3 by hand (note 11); 4 and 5 in BATS. shellcheck, Pint and Biome clean. `prepare.sh` gained `nodeapps`, `nodeapps-clean` and `https`.
