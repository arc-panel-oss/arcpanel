# E4 — App Store: Docker apps — design

**Status:** Implemented (2026-10-05, see §13) · **Epic:** E4 · **Base design:** [08 App Store](../../design/08-app-store.md) §3–§5, §7–§8 · **Previous specs:** [E12](./2026-10-05-004-e12-port-registry-design.md), [E6 batch 1](./2026-10-05-005-e6-templates-batch1-design.md), [E13](./2026-10-05-006-e13-node-manager-design.md), [E14](./2026-10-05-007-e14-node-apps-design.md) · **ADRs:** [0003 Docker mode](../../adr/0003-docker-mode.md), [0001 view layer](../../adr/0001-view-layer.md) · **Roadmap:** [§3 E4](../../roadmap.md)

## 1. Summary

E4 lets a user install a curated Docker Compose app from a catalog, bind it to one of their web domains and run it behind NGINX with HTTPS, without SSH. One root Docker Engine runs every app; only `v-*` commands touch it. The catalog ships with ArcPanel; every app version is pinned by image digest. The panel renders the Compose project from the catalog plus an override file of its own that forces every service to run as the hosting user, without capabilities, with the user's limits, and with ports from the port registry (E12). Users manage apps from a store, a "My apps" list and an app page: install, logs, settings, update with automatic rollback, database dumps for backups, delete. Suspend, delete, backup, restore and reboot keep apps consistent without changes to upstream commands.

Design document 08 stays the reference for intent. This spec records the decisions of the 2026-10-05 brainstorm, the scope of E4 and where it differs from 08.

The upstream installers are not changed.                                                                                                                                                                                                                                                                                    |

The panel never edits the catalog's Compose file: everything ArcPanel enforces lives in a generated `compose.arcpanel.yaml` override, and the merged result (`docker compose config --format json`) is checked. Also recorded: users can create the domain they need first on the Web Domains page (no "create domain" shortcut in the install form); Let's Encrypt works as for any domain.

## 4. Scope

### In scope

1. `func/docker.sh` and the commands of §5; the catalog with six apps; the manifest schema and its CI check.
2. Package keys `DOCKER`, `DOCKER_APPS`, `DOCKER_CPUS`, `DOCKER_MEMORY` (sidecar, reseller bound, `developer.tenancy`); server keys `DOCKER_SYSTEM`, `DOCKER_DATA_ROOT`.
3. The task runner for `install`, `update`, `rollback` and `snapshot`; dumps; the two cron lines (5-minute check, daily dumps).
4. Hooks `70-dockerapps.sh` for `post_suspend_user`, `post_unsuspend_user` and `pre_delete_user`; the panel's web domain delete action removes the domain's app first (as E14 implementation note 7).
5. `DockerAppService`, `DockerCatalog`, `DockerEngineService`, records, `DockerPolicy`, capabilities, routes, navigation entries, Docker keys in the Packages form.
6. The `docker-apps` island, the admin Docker page, the Dashboard card and the user detail card.
7. BATS, Pest, Vitest and Playwright tests; the documentation changes of §12.

### Out of scope

- Catalog refresh from a signed Git repository and per-user catalog sources (E33; 08 §9 question 2).
- Log streaming over the web terminal WebSocket (E18).
- System packages and the "System" tab (E5).
- Ghost, Nextcloud, Portainer and any image that needs root.
- Rootless Docker or Podman (ADR-0003, post-2.0).
- Docker on Apache-only servers (no NGINX in front).
- The Backup Exclusions toggle per app (moves with that page in E7).
- Any change to the legacy `web/` app or to upstream commands.

### Done when

1. An administrator installs the Docker engine from the admin Docker page.
2. A user on the `developer` package installs Uptime Kuma on a domain from the store and it answers over HTTPS within 5 minutes; the app page shows the install log live, then the container logs.
3. All six catalog apps install with their default variables on `arcpanel-test` and pass their health check; every container runs as the user's uid with no capabilities.
4. A manifest or Compose file that asks for `privileged`, a capability, a device, the host network, the Docker socket, a bind mount outside `data/`, a named volume, a build or an image without a pinned digest is refused by `v-check-docker-catalog` and by `v-add-docker-app`.
5. Updating an app to a newer catalog version works; an update whose health check fails rolls back automatically and the data written before the update is still there.
6. After backup → delete user → restore, the apps are running on the same ports with their data within 5 minutes; after the distribution restarts, they answer without anyone logging in; suspending the user stops them and unsuspending starts them.
7. A reseller sees the apps of its customers and gets 404 for another tree; a user on the `default` package has no Docker apps entry and the routes answer 403; an app beyond `DOCKER_APPS` fails with `E_LIMIT` and the page says why.
8. Deleting an app removes its containers and network, frees its ports, restores the previous template and removes `~/apps/<name>/` (or keeps `data/` with "keep data").

### 5.2 Library `func/docker.sh`

Record access under `data/users/<user>/dockerapps.lock` (`dockerapp_get`, `dockerapp_set`, `dockerapp_line`, `dockerapp_count`, `dockerapp_remove`); validation (`dockerapp_name_valid`, variable validation by type); catalog helpers (`docker_catalog_dir`, `docker_manifest SLUG VERSION`, `docker_latest_version SLUG`); the renderer (§5.4); the checks (§5.4); `dockerapp_compose USER NAME ARGS…` (runs `docker compose -p ap-<uid>-<name> --project-directory <rendered dir> -f compose.yaml -f compose.arcpanel.yaml --env-file .env`); `dockerapp_as_user USER CMD…` (`runuser -u` for every read or write in the home directory); `dockerapp_copy_write`; template switching shared with `func/nodeapp.sh` (moved into a common helper where both need it, without changing behaviour); `dockerapp_health USER NAME` (§5.5).

### 5.3 Catalog format

`manifest.json` (schema `docs/design/schemas/docker-app.schema.json`):

```json
{
	"schema": 1,
	"slug": "uptime-kuma",
	"version": "1.23.16",
	"name": "Uptime Kuma",
	"summary": "Self-hosted monitoring with status pages.",
	"description": "Markdown shown on the detail page.",
	"category": "monitoring",
	"homepage": "https://github.com/louislam/uptime-kuma",
	"license": "MIT",
	"admin_only": false,
	"arch": ["amd64", "arm64"],
	"images": ["louislam/uptime-kuma:1.23.16@sha256:<digest>"],
	"requirements": { "memory": "256M", "disk": "1G" },
	"limits": { "memory": "512M", "cpus": "0.5" },
	"ports": {
		"web": { "service": "app", "container": 3001 },
		"ssh": { "service": "app", "container": 2222, "description": "Git over SSH" }
	},
	"volumes": [{ "name": "data" }],
	"variables": [
		{
			"name": "TZ",
			"label": "Time zone",
			"type": "string",
			"default": "{{server.timezone}}",
			"required": true,
			"pattern": "^[A-Za-z_/+-]+$"
		}
	],
	"healthcheck": { "type": "http", "path": "/", "expect": [200, 302], "timeout": 180 },
	"dumps": [{ "service": "db", "command": "pg_dump -U umami umami", "file": "umami.sql" }],
	"post_install": "Open {{url}} and create the first account.",
	"changelog": "https://github.com/louislam/uptime-kuma/releases"
}
```

- `slug` `^[a-z][a-z0-9-]{1,31}$` and equal to the directory name; `version` equal to its directory name; `category` one of `monitoring`, `automation`, `dev`, `cms`, `storage`, `security`, `database`, `analytics`, `other`.
- `ports.web` is optional (Redis has none; then no domain is bound). Port names are `^[a-z][a-z0-9]{0,15}$`. A port's `service` must exist in the Compose file.
- Variable `type` is `string`, `int`, `bool`, `enum` (with `options`), `password`, `email` or `url`; `password` variables are secret: generated when left empty, never returned in clear by `v-list-docker-app-env`, never in logs. A variable may be `immutable` (set at install only, such as a database password the data was initialised with). Defaults may use `{{server.timezone}}`, `{{domain}}`, `{{url}}`, `{{user.email}}` and `{{random:N}}`. Values are one line, at most 1024 bytes, and are refused when they contain `'`, `"`, `$`, `` ` `` or `\`.
- `healthcheck.type` is `http` (through the web port on `127.0.0.1`) or `container` (every service `running`, and `healthy` when the image defines a health check).
- `compose.yaml` is a plain Compose file. It may use the variables of the manifest and `ARC_UID`, `ARC_GID`, `ARC_DOMAIN`, `ARC_URL`, `ARC_DATA_<VOLUME>` (upper case) through `${…}`. It must not declare `ports`, `user`, `cap_add`, `cap_drop`, `security_opt`, `cgroup_parent`, `restart`, `logging`, `cpus` or `mem_limit`: the override owns them. Images must be one of the manifest's `images`.

`v-check-docker-catalog [DIR]` validates every manifest with `jq` against the rules above, renders each app with default variables into a temporary directory and runs the checks of §5.4 on the merged configuration. It runs in CI with a Docker CLI available and in BATS on `arcpanel-test`.

### 5.4 Rendering and checks

1. `.env` is written from the variables (validated, defaults interpolated, secrets generated) plus `ARC_*` values.
2. `compose.arcpanel.yaml` is generated for every service of the catalog file: `user: "<uid>:<gid>"`, `cap_drop: [ALL]`, `security_opt: ["no-new-privileges:true"]`, `cgroup_parent: user-<uid>.slice`, `cpus` and `mem_limit` (the app's `CPUS` and `MEMORY` as the ceiling of each service; Compose has no project-wide limit, so `cgroup_parent` is what bounds the user's total), `restart: unless-stopped`, `logging` (`json-file`, `10m` × 3), `labels` (`top.arcpanel.user`, `top.arcpanel.app`), and `ports` for the services named by the manifest's ports: `127.0.0.1:<host port>:<container port>` (`0.0.0.0` when the registry entry is public).
3. `docker compose … config --format json` merges the files. The result is refused (`E_FORBIDEN`, nothing started) when any service has `privileged`, `cap_add`, `devices`, `network_mode`, `pid`, `ipc`, `userns_mode`, `build`, `volumes_from`, `extra_hosts` other than `host.docker.internal:host-gateway`, a `user` other than the user's, an image not in `images`, a volume of type `volume` or `tmpfs` larger than 256 MB, a bind source outside `/home/<user>/apps/<name>/data/`, or a bind source that is `docker.sock`; or when the project declares an `external` network or volume, or any top-level `volumes`, `secrets` or `configs` with a host `file`.
4. Before every `up`, each bind source is checked: it exists, is a directory and not a symlink, is owned by the user, and its `realpath` is inside `/home/<user>/apps/<name>/data/`. Missing volume directories are created as the user.

### 5.7 Updates, backups and convergence (M3)

| Unit                                                         | Behaviour                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| task `update [VERSION]`                                      | default the latest catalog version; refused when not newer. `STATUS='updating'`; `compose stop`; snapshot `data/` as the user to `.snapshots/<old version>.tar.zst` (free disk at least twice the data size, else `E_DISK` before stopping); copy the new `compose.yaml`, keep the variables (new variables get their defaults), render and check; pull; `up -d`; health check. ## 11. Risks

| Risk                                                                | Mitigation                                                                                                                                                              |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A container escape is a host compromise (root engine)               | D3: no root inside, no capabilities, `no-new-privileges`, curated images pinned by digest; recorded in ADR-0003; administrators can keep `DOCKER='no'` in every package |
| An image cannot run as an arbitrary uid                             | the catalog entry overrides the entrypoint or environment where the image allows it; otherwise MinIO replaces the app (D6) and the implementation notes say which       |
| `cgroup_parent` with a user slice fails on a system                 | D12 fallback to per-app limits, recorded in the implementation notes                                                                                                    |
| Registry rate limits or no network                                  | `E_CONNECT` with the registry message; "Retry"; digests make retries reproducible                                                                                       |
| Disk fills with images                                              | `requirements.disk` checked; `v-check-sys-docker repair` prunes unused images older than 7 days and reports usage above 85 %                                            |
| A crash-consistent copy of a running database in the nightly backup | D10 dumps 15 minutes before the backup; documented that the CLI `v-backup-user` alone only has the last dumps                                                           |
| Docker's address pools collide with the host network                | `default-address-pools` `172.30.0.0/16`, changed in `daemon.json` by the administrator when it collides                                                                 |
| The user edits files under `~/apps/<name>/`                         | the copies are only import sources and are validated (D4); bind sources are checked before every `up` (D3)                                                              |
| Secrets in logs                                                     | values only travel in temp files and `.env`; `log_event` records the command line without the file content; `v-list-docker-app-env` never returns secrets               |

## 13. Implementation notes (2026-10-05)

These notes win over the sections above where they differ.

1. **Catalog (D6).** Umami was replaced by **Miniflux with PostgreSQL**: Umami's Prisma client writes into `node_modules` at start, which an arbitrary uid cannot do. MinIO, the planned fallback, is no longer published on Docker Hub. Miniflux keeps the database app with dumps (D10). The six apps are Uptime Kuma `2.5.5-rootless`, n8n `2.41.7`, Gitea `1.27.3-rootless` (extra port `ssh`), Vaultwarden `1.37.3-alpine` (`ROCKET_PORT` `8080`), Miniflux `2.3.3-distroless` with `postgres:16.15-alpine`, and Redis `8.8.3-alpine` (extra port `redis`, password passed on standard input, container health check). Icons are neutral monograms.
2. **Generated values (§5.3).** Only variables whose default is `{{random:N}}` are generated (the catalog JSON marks them `random`). A required variable without a default, such as Miniflux's `ADMIN_PASSWORD`, must come from the user. `v-check-docker-catalog` supplies dummy values for such variables, so every app version renders and passes the checks.
3. **Compose checks (§5.4).** The merged project is read with `docker compose config --no-env-resolution --format json`, so `env_file` stays a reference and secrets never reach the checked output. `tmpfs` volumes are allowed next to bind mounts under `data/`. `cgroup_parent: user-<uid>.slice` works on cgroup v2 (Ubuntu 24.04 under WSL), so the D12 fallback was not needed.
4. **Port registry ids (D5).** The web port is `docker:<name>`, and an extra port is `docker:<name>.<port>`, because the E12 app pattern allows one colon. Extra ports are bound to `127.0.0.1` while private. A port made public through E12 is bound to `0.0.0.0` and reaches the container through Docker's own DNAT rules. `v-check-sys-docker repair` renders the project again when the registry flag and the published address differ.
5. **Task runner (D7).** The task runner and the library avoid upstream's global `arg`, which `is_format_valid` overwrites, so their argument variables are `version` and `target`. A detached task closes the record lock's file descriptor only when the caller holds one. Every `docker` call of a task runs under a 1800-second watchdog (`docker_with_timeout`).
6. **Logs (D8).** `v-list-docker-app-logs` runs `docker compose logs --timestamps --no-log-prefix` with `--since`, and adds the service name from a per-service call, so lines of different services merge in time order.
7. **Delete.** `v-delete-docker-app` also removes the app's images when no other container uses them. `v-check-sys-docker repair` prunes unused images older than seven days.
8. **A deleted web domain.** Upstream `v-delete-web-domain` has no hook (E14 note 7). After the panel deletes a web domain, it runs `v-delete-docker-app` for the app on that domain and keeps the app's data. For a domain deleted on the CLI, `v-check-sys-docker` reports `domain-missing`, and `repair` removes the app the same way.
9. **Routes (§6.3).** The engine page is `GET /app/server/docker`, with JSON under `/app/server/docker/api` (`status`, `install`, `task`): a path under `/app/docker/` would collide with a user named `api`. `GET /app/docker/{user}/api/options` replaces `domains`. It returns the free domains, the instance names in use and whether the package has room, which is everything the install form needs in one call.
10. **Cron and upgrade (§9).** `v-add-sys-docker` writes two cron lines: `v-check-sys-docker repair` every 5 minutes, and `v-backup-docker-apps all` 15 minutes before the `v-backup-users` line. The ArcPanel `1.1.0` upgrade step re-runs `v-add-sys-docker` when `DOCKER_SYSTEM='yes'`. `test/dev-sync.sh` mirrors `install/common/apps` with `--delete` and re-runs `v-add-sys-docker` when the engine is installed.
11. **Test catalog.** `test/fixtures/docker-catalog/` holds busybox apps pinned by digest: `tiny` `1.0.0`, `2.0.0` and `3.0.0`, plus `worker` `1.0.0`. Version `3.0.0` fails on purpose: it deletes a data file and exits, which exercises the rollback. `ARC_DOCKER_CATALOG` points the commands at that folder.
12. **Server keys in `v-list-sys-config` (§5.1).** The panel reads `DOCKER_SYSTEM` for the navigation entry, the user detail card and the store. `v-list-sys-config` lists its keys explicitly, so it now also prints `DOCKER_SYSTEM` and `DOCKER_DATA_ROOT` in its `json` and `shell` output. This is the same output-only change E1, E11 and E12 made for their keys. The Pest fake answered with any key, so only the first Playwright run found the missing key; `test/arcpanel-docker.bats` now checks it.
